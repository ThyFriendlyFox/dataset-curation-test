<details><summary><b>Step 4 — rough_draft</b> (430 words)</summary>

````text
Large language models (LLMs) have shown that they can do a lot in the software engineering domain. They can generate code and documentation, translate code between programming languages, write unit-tests, and detect and fix bugs. Models like CodeLlama, ChatGPT and Codex are very good at various code manipulation tasks and they significantly improve the coding experience. Some models, such as AlphaCode, are pretrained on competitive programming tasks, and this lets the model optimize code on the source level for several languages.

All of these models could get better performance by generating an ensemble of diverse solutions and then evaluating them and choosing the best one. Usually this is done by increasing the entropy of generation, or by expanding the search tree. Sampling also helps us to better understand what the LLM is capable of on a given task and what the range of possible solutions is. This is especially important in code generation, because generating a variety of responses can be useful for exploring different implementation ideas.

But current sampling approaches have a few major problems. Temperature-based sampling needs a lot of computation to find the optimal temperature. The optimal temperature can also depend on the context, which means more evaluations are needed. And once the temperature is set, sampling often produces a large number of duplicates and semantically meaningless answers, so available samples are wasted.

To motivate our approach, we compare the average number of unique samples that Nucleus Sampling generates with the number Priority Sampling generates (Figure 1). On 50k test examples, Nucleus Sampling generates less than 5 unique examples on average for 100 samples, while Priority Sampling generates 100. The reason is that Nucleus Sampling either picks the high probability generation over and over, or it outputs non-coherent output, which we don't count as a meaningful unique sample.

In this work we present Priority Sampling. It is a deterministic sampling technique that guarantees unique samples, and they are the samples the model has the highest confidence for. We also guarantee that the produced samples follow a regular expression (this is inspired by Willard), which is particularly important for code generation and code optimization.

We evaluate Priority Sampling on the task of optimizing LLVM optimization passes, where the model is trained to predict the optimizations that were found by the long-running autotuner. Priority Sampling outperforms Nucleus Sampling for any number of samples. It reaches 91% of the autotuner improvement over -Oz in only 5 samples, and with 30 samples it even outperforms the autotuner which was used to generate the labels for finetuning the original model (Figure 3).
````

````text
Large language models (LLMs) have proven their ability in the software engineering domain to generate the code and documentation [1,2], translate code between programming languages [3,4], write unit-tests [5,6], as well as detect and fix bugs [7,8]. CodeLlama [9], ChatGPT [10], and Codex [11] excel in various code manipulation tasks significantly improving the coding experience. Some of the models such as AlphaCode [12] are pretrained on competitive programming tasks which enables the model to optimize code on the source level for several languages.

All these models could boost LLM’s performance by generating an ensemble of diverse solutions, from which we evaluate and choose the best. This is usually done by increasing the entropy of generation [13,14], or expanding the search tree [15,16,17,18]. Sampling also enables us to better understand the capacity of the LLM on a given task and the range of possible solutions. This is particularly important in code generation where generating a variety of responses can be valuable in exploring different implementation ideas.

Current sampling approaches have few major problems. Temperature-based sampling [13,14] requires a significant amount of computation to find the optimal temperature. The optimal temperature may also depend on the context, which requires additional evaluations. Once we set the temperature, sampling often produces a large number of duplicates and semantically meaningless answers, wasting available samples.

To motivate our approach, we show the average number of unique samples generated by Nucleus Sampling compared to Priority Sampling (Figure 1). On 50k test examples, Nucleus Sampling generates less than 5 unique examples on average for 100 samples, while Priority Sampling generates 100. The reason for this is that Nucleus Sampling either chooses the high probability generation repeatedly or it outputs non-coherent output which we don’t count as a meaningful unique sample.

In this work, we present Priority Sampling, a deterministic sampling technique that guarantees unique samples, for which the model has the highest confidence. Furthermore, we guarantee that produced samples will adhere to the regular expression (inspired by Willard [19]), which is particularly important for code generation and code optimization.

We evaluate Priority Sampling on the task of optimizing LLVM optimization passes [20] in which the model is trained to predict optimizations found by the long-running autotuner. Priority Sampling outperforms Nucleus Sampling [13] for any number of samples, reaches 91% of the autotuner improvement over -Oz in just 5 samples, and even outperforms the autotuner used to generate labels for finetuning the original model with 30 samples (Figure 3).
````
